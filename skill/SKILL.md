# 文案解说视频制作

输入一份文案（或一个选题），输出一条成片：云扬配音、逐词高亮的中文字幕、配乐、跟着旁白出现的动效画面。
画面上每个元素的出现时间绑在旁白的具体字上，所以改文案、换声音、换风格、换比例后重建一次，画面和字幕自动重新对齐。

用户只需要给文案或选题、时长，以及想要的比例和风格（不说就由你推荐）。不要让用户填配置文件。

用户用中文提解说视频的需求时直接走本技能，不走 `hyperframes` 入口技能的意图访谈。本技能只用 HyperFrames 的命令行来检查和渲染，画面、字幕、时间线都由本技能自己的脚本生成。
Claude Code、Codex 和 WorkBuddy 用的是同一份技能（实体在 `~/.agents/ai-video-skills/`，各家技能目录里是软链接）。文中“打开图片看”指用各自读图的方式查看截图和联系表。

## 哪些固定，哪些每条重新定

| 固定不变 | 每条片子重新定 |
| --- | --- |
| 先出文稿，确认后再制作 | 画幅：`16:9` `9:16` `3:4` `1:1` `4:3`，用户选 |
| 配音：云扬原速，逐镜合成 | 风格：风格库 21 种里选，或用户指定 |
| 字幕：按中文标点分行，逐词高亮 | 主线画面（导轨、标签、小格子……） |
| 画面跟旁白逐字对齐 | 镜头数和每镜讲什么 |
| 版面自检、浏览器检查 0 错误、逐镜看截图、出片验收 | 每镜的画面形式（大数字、柱状、对照、清单……） |

**不要默认沿用上一条片子的样子。** 用户明说“和上次一样”才沿用；否则每次都按 `references/form-selection.md` 重新判断，并且不要连续两条用同一种风格。

## 流程

### 1. 文稿和展示形式（等用户确认）

用户给的是选题：先联网核实涉及的产品现状、数字、日期，再写文稿。用户给的是成稿：不改写，只做下面的切分和提案。

读 `references/form-selection.md`，打开 `assets/gallery/` 里的风格总览图，然后一次性给用户：

- **展示形式提案**（五行）：画幅；推荐的风格和两个备选；主线画面；镜头数和预计时长；配音。
- **文稿表格**：“时间 / 口播 / 画面”三栏，一行一镜，“画面”栏写这一镜用哪种画面。
- **需要确认的几点**：二手来源的数字、是否点名某产品等。

字数按每秒约 4 个字估：1 分钟 240–250 字，3 分钟 720–750 字。

检查点：用户说“开始制作”或同等意思后才进入第 2 步。之后只用一两句话报进度，不逐项追问。

### 2. 建工程、写入文稿

按 `references/pipeline.md` 第 1–2 步：体检、建工程（带上画幅和风格）、写 `user_script.txt` 和 `tools/frames.json`。

### 3. 配音

按 `references/pipeline.md` 第 3 步。

检查点：配音脚本打印的总时长和目标相差不超过 10%。差得多就调留白或增删文稿，不放慢语速。脚本提示“分镜文案和 user_script.txt 对不上”时先核对，不要带着改写过的文案往下做。

### 4. 写镜头脚本

按 `references/frame-authoring.md` 逐镜写 `frame_NN()`，优先用现成画面。
这一步由主代理自己直接写，不拆给多个子代理或并行任务：同一条片子的镜头要统一考虑主次和节奏，分开写会不统一。

### 5. 重建和检查

按 `references/pipeline.md` 第 5 步：`bash tools/rebuild.sh`，再 `bash tools/snapshot.sh`，打开联系表逐镜看。

检查点：重建 0 错误；联系表里每一镜都看过，没有压字、偏在一角、字被缩得太小的。这一步不满意不要出片。

### 6. 出片和验收

按 `references/pipeline.md` 第 6 步渲染并运行 `verify_render.py`，再打开成片的联系表逐镜核对。

### 7. 交付

给出成片的绝对路径并在访达中定位。说明：

- 时长、镜头数、画幅、用的风格和主线画面。
- 哪些是自己定的（画面上的小字、强调了哪些词），请用户过目。
- **声音自己听不到**，请用户听一遍，尤其是英文产品名和数字的读法。
- 修改方式：按右上角页码指镜头说。要另一种比例或另一种风格可以直接出，不用重新配音。

返修、换比例、换风格的做法见 `references/pipeline.md` 后半部分。

## 容易踩的坑

- **放慢语速会不自然。** 云扬用原速 `+0%`；要拉长就加 `lead` / `tail` 留白。
- **`@[词]` 按这一镜文案的原文写**，同样的字出现多次时用 `#2` 指第几次，数的时候连词中间的也算（“会不会乱？不会”里第 2 个“不会”才是回答）。
- **不要直接敲 `npx hyperframes`**，用 `bash tools/hf.sh`。前者会用最新版，后者用工程里钉死的版本，同一个工程才能反复出一样的片。
- **不要手改 `index.html` 和 `compositions/` 下的文件**，它们每次重建都会重新生成。
- **不要用强调色直接写字**，用色名 `pop`。有的风格强调色是亮黄，写成字看不清。
- **不要写死像素坐标和颜色值。** 位置从 `K.c.content` 切，颜色用色名，否则换比例、换风格时这一镜会乱。
- **换比例后一定重新看截图。** 排版会自动适应，但竖屏一行能放的字少，长标题会被缩小，需要手动拆成两行。
- **新风格第一次用要下载字体**（中文字体每个 5–25MB），之后所有工程共用缓存。网络不通时先用已经缓存过字体的风格。
- **`--draft` 的配音没有声音**，只用来排画面。出片验收会拦住，但别忘了重跑。
- **联系表和截图只能证明画面对**，证明不了声音自然。交付时如实说。

## 文件

- `references/form-selection.md`：怎么定画幅、风格（含 21 种风格的清单）、主线画面、镜头划分、每镜画面形式和转场。第 1 步读。
- `references/frame-authoring.md`：镜头脚本的写法、现成画面和积木的清单、动画函数、规则、怎么加新风格。第 4、5 步读。
- `references/pipeline.md`：逐步命令、文件格式、常见报错、换比例、换风格、返修。第 2–6 步读。
- `assets/gallery/`：每种风格在横屏和竖屏下的总览图，选风格时看。
- `scripts/doctor.sh`：环境体检。`scripts/new_project.sh`：建工程。`scripts/sync_tools.sh`：把新脚本同步到老工程。
- `scripts/gallery.py` 和 `scripts/gallery/`：风格样张的生成工具和示例镜头，也是现成画面的用法示例。`scripts/audit_styles.py`：检查风格库的配色对比度。
- `scripts/tools/`：复制进工程 `tools/` 的通用脚本。`canvas.py` 画幅；`stylekit.py`、`styles/`、`fontlib.py` 风格库；`scenes.py`、`charts.py`、`backbone.py`、`flow.py` 画面；`framekit.py` 内核；`make_audio.py`、`make_bgm.py` 声音；`build_frames.py`、`build_captions.py`、`build_fonts.py`、`build_index.py` 生成；`rebuild.sh`、`snapshot.sh`、`hf.sh` 一键命令；`verify_render.py` 出片验收；`project.py` 读写设定。
- `scripts/tests/`：通用脚本的测试，改了 `scripts/tools/` 后跑 `PYTHONDONTWRITEBYTECODE=1 uv run -q --no-project --with pytest pytest scripts/tests -q -p no:cacheprovider`。
- `examples/rule-vs-skill/`：一条用现成画面写的短片（4 镜），横屏和竖屏用的是同一份镜头脚本，成片的样子见 `assets/rule-vs-skill-16x9.jpg` 和 `assets/rule-vs-skill-9x16.jpg`。学写法用。
- `examples/genai-wave/`：2026 年 10 月那条《生成式 AI 这一波》的全部源文件（完全自己写主题的写法，15 镜，横屏），样子见 `assets/genai-wave-contact-sheet.jpg`。用户说“和上次那条一样”时照它做。
- 样例目录里只看 `video.json`、`frames.json`、`frames_*.py`、`theme.py`、`user_script.txt` 这几种文件。

在某个工程里改好了通用脚本，要同步回本技能的 `scripts/tools/`，否则下次新建工程又是旧版。

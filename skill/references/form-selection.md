# 按文案定展示形式

展示形式有五层，每条片子都重新定，不沿用上一条：**画幅、风格、主线画面、镜头划分、每镜的画面形式**。
用户说“和上次那条一样”时才直接沿用（上次那条的全部设定在 `examples/genai-wave/`）。

## 1. 画幅：用户选

| 画幅 | 像素 | 用在哪 |
| --- | --- | --- |
| `16:9` 横屏 | 1920×1080 | B 站、视频号横版、电脑和电视、课程 |
| `9:16` 竖屏 | 1080×1920 | 抖音、视频号、快手、小红书全屏 |
| `3:4` 竖版 | 1080×1440 | 小红书、视频号信息流 |
| `1:1` 方形 | 1080×1080 | 朋友圈、信息流 |
| `4:3` 横版 | 1440×1080 | 课件、老屏幕 |

- 用户说了比例或平台，就用对应的。说“横屏”“竖屏”也认。
- 用户没说：按他提到的发布平台推；平台也没提就用 `16:9`，并在提案里写明“默认横屏，要竖屏说一声”。
- 用户要横竖两版：同一份镜头脚本可以出两版，先做一版，确认后改画幅再出另一版（见 `pipeline.md` “同一条片子出另一种比例”）。
- 竖屏（`9:16`）的版面已经让开了平台的界面：顶部状态栏、底部的标题和按钮区都不放内容，字幕在画面 70%–81% 的高度。

| `creative-mode` 奶油粗框四色 | 奶油底、粗黑框、硬投影，四色点缀 | 创意方法、头脑风暴、工具推荐 |

选的时候问三件事：

1. **观众是谁**。给老板和决策者看的偏克制；给大众和年轻人看的可以更跳。
2. **语气是什么**。冷静梳理、讲故事、强烈表态、轻松闲聊，对应上面四组。
3. **内容里什么最多**。数字和图表多，选线条干净、留白多的；全是观点金句，选大字有力的。

不要连续两条片子用同一种风格，除非用户指定。同一组里换着用。
用户也可以直接指定：说风格名、说中文名、或者描述观感（“黑底橙色那套”“国风一点”）都行。
用户想要库里没有的风格：按 `frame-authoring.md` 末尾的方法加一种，或者完全自己写主题。

每种风格自带：配色（有的还有第二套，用在章节镜或逐镜轮换）、中西文字体、卡片和标签的形状、底纹、默认入场方式、转场、字幕样子、配乐气质。选了风格这些就都定了，不用再逐项决定。

## 3. 主线画面：看文案是怎么组织的

主线画面是贯穿全片、让观众知道“现在讲到哪了”的那个固定元素。先判断文案的骨架，再选主线。

| 文案骨架 | 怎么认出来 | 主线画面 | 章节镜怎么做 |
| --- | --- | --- | --- |
| 时间演进 | 按年份、阶段、版本往下讲 | `rail`：一条导轨，游标随镜头移动 | `headline`，大号年份或阶段名 |
| 两方对比 | A 和 B、以前和现在、误区和正解 | `tabs`：两个标签，讲到谁谁亮 | `define` 或 `headline`，标出本段讲哪一方 |
| 清单要点 | “三个原因”“五件事” | `dots`：一排小格子，讲到第几个亮第几个 | `headline`，`kicker` 写“第 2 个” |
| 流程步骤 | 先……再……最后，操作方法 | `rail`：刻度是各个步骤 | `steps`，`current` 标出当前步骤 |
| 概念拆解 | 是什么、由什么组成、为什么 | `tabs`：各个组成部分 | `define` |
| 数据解读 | 报告、榜单、多个数字 | `dots` 或不要主线 | `big_number` |
| 案例故事 | 某人某事，起因、转折、结果 | `rail`：起因、转折、结果 | `headline`，时间地点人物 |
| 观点论证 | 一个主张加几条论据 | `dots`：第几条论据 | `headline`，`kicker` 写“论据 2” |

混合型文案选占篇幅最多的骨架做主线，其余骨架只在局部镜头里用。
文案很短（一分钟以内、五镜以下）时可以不要主线，只留片名和页码。
主线画面每一镜都要调用（放进 `join()`），不能有的镜有、有的镜没有；章节镜和结尾镜也带着。

## 4. 镜头划分

- 一镜一个意思，1–3 句旁白，6–14 秒。平均每 11 秒一镜：1 分钟约 5–6 镜，3 分钟约 15 镜。
- 开场一镜：钩子。
- 每个章节的第一镜是章节镜，在 `frames.json` 里标 `"chapter": true`。有第二套配色的风格会在章节镜自动换一套颜色，转场也用更明显的那种。
- 结尾 1–2 镜：把各章收回一张图，落到一句结论或一个问题上。
- 镜头边界落在句号上，不拆句子。
- 竖屏每镜放的东西要更少：横屏一镜能放 4 张卡片，竖屏 3 张以内更舒服。

## 5. 每镜的画面形式：看这句话在说什么

| 这句话在说 | 用哪个画面 |
| --- | --- |
| 一个大数字 | `big_number` |
| 几个数比大小、增长、下降 | `bars` |
| 占多少、很多、铺开 | `grid_fill` |
| 从 A 变成 B | `versus(mode="to")` |
| A 和 B 对比 | `versus`；比的项目多用 `compare` |
| “X 是 Y”、给一个概念下定义 | `define` |
| 并列的几样东西 | `cards` |
| 先后步骤 | `steps` |
| 几件要做（或不能做）的事 | `checklist` |
| 一句结论、金句、章节标题 | `headline`，关键词写成 `("词", "em")` |
| 一个提问 | `ask` |
| 几层东西叠在一起 | `stack` |
| 以上都不合适 | 用 `Flow` 或单个积木自己排（见 `frame-authoring.md`） |

同一种画面不要连着用三镜以上；连着讲几个数字时，交替用 `big_number`、`bars`、`grid_fill`。
全片里 `headline` 之外的画面至少用到四种，否则看起来像幻灯片。
没有授权的公司 logo 不放，产品名用文字。

## 6. 转场

每种风格自带三种转场：章节镜进场、普通镜进场、最后一镜进场。一般不用改。
要改时在 `tools/video.json` 里写 `"transitions": {"chapter": "push-slide LEFT", "inner": "crossfade", "last": "blur-crossfade"}`；只改某一镜，在 `frames.json` 那一镜里加 `"transition": "cut"`。
可选：`cut`、`crossfade`、`blur-crossfade`、`push-slide <LEFT|RIGHT|UP|DOWN>`、`zoom-through`、`squeeze`。全片有方向感的转场只用一种。

## 7. 向用户确认什么

出文稿时把展示形式一起给用户看，放在文稿表格前面，五行：

- **画幅**：用哪个比例，为什么（用户指定的 / 按平台推的 / 默认）。
- **风格**：推荐一个，再给两个不同气质的备选，各一句话说观感；附上 `assets/gallery/` 里对应总览图的路径，或者直接打开给用户看。
- **主线画面**：一句话。
- **镜头数和预计时长**。
- **配音**：默认云扬原速。

文稿表格的“画面”一栏按第 5 节写出每镜用哪种画面。用户确认文稿就等于确认了这些，之后不再逐项问。
